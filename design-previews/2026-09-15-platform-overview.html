技术

三个决定产品上限的工程决策

整套系统刻意保持极简：不引入消息队列、向量数据库、前端状态管理库或 UI 组件库。 在 5–50 人团队的规模下，这些是纯粹的复杂度负债。

可插拔 AI 引擎适配层

业务层只依赖一个 Protocol，接口只有三个方法。Dify 与任何 OpenAI 兼容端点 （DeepSeek、通义等）自由切换，业务代码零改动——客户已有的模型资产可以直接接进来。

零代码自定义智能体

写一段提示词 + 定义参数表单，就得到一个智能体。它和内置智能体被适配到 同一个接口，因此在「单独运行 / 工作流步骤 / 定时调度」三条路径上行为完全一致。

定时执行 + 结果传递

画布连线编排多步 AI 任务，{{prev_output}} 自动把上一步结果喂给下一步。 支持 cron 与固定间隔，调度器保证重启不重复注册、任务不并发堆积。 

# 业务层唯一依赖的接口 —— 只有三个方法
class AiEngine(Protocol):
    async def chat(...)            -> str
    async def knowledge_query(...) -> KnowledgeAnswer
    async def stream_chat(...)     -> AsyncIterator[str]

# 两个实现，环境变量切换：
#   DifyEngine              → 复用 Dify CE Service API（headless）
#   OpenAICompatibleEngine  → 标准 /chat/completions，适配 DeepSeek / 通义等
# 未配置密钥时优雅降级：普通端点返回 503，流式端点在事件流中报错后收尾

RAG：够用就好，不堆中间件

解析 → 切片 → 检索 → 拼装提示词。检索用关键词算法（中文滑动二元组切词）， 在几千篇文档量级下效果足够，且零依赖、可解释、可调试。接口是 Protocol，将来换向量检索不动上层。

副驾不依赖 function calling

用一次非流式调用让模型输出 JSON 意图，正则抓取 + 动作白名单校验，非法一律回退为普通问答。 好处是两个引擎通用，不被某家模型的能力差异绑住。

数据库迁移版本

类型系统强制的前后端契约

前端数据层的接口定义由演示模式的 mock 反向锁定——真实 API 与 mock 必须逐方法镜像， 漏一个方法 tsc 直接报错。

演示模式：任何环境都能演

后端未连接时自动降级为完整的演示态，界面全部可交互，流式输出照常。 客户现场没网也能演，而后端就绪后自动切真实数据，无需改代码。

安全防护已内建

JWT 与 bcrypt 认证、四桶独立限流、跨租户统一 404（不泄露资源存在性）、 网页抓取带 SSRF 防护（拒私有地址、逐跳校验重定向）。

私有化交付成本极低

一个 Compose 文件、一台 2C4G 服务器即可完整部署，可运行在完全离线的内网。 回滚只需一条命令，容器启动自动执行数据库迁移。

问答

最常被问到的七个问题

和飞书 / Notion 有什么区别？
不替代，做它们的 AI 执行层。信息可以继续放在原工具，雅秩 负责让 AI 真的去干活。
和 Dify / Coze 有什么区别？
Dify 是给开发者搭 AI 应用的平台，雅秩 是给团队直接用的成品办公台。而且可以复用 Dify 做引擎——已有 Dify 直接接进来。
数据安全吗？
支持完全私有化部署在内网、可离线运行；数据不出自己的服务器；多租户隔离，跨租户访问一律 404。
要换掉现在的工具吗？
不需要。可以只用一个模块起步，比如先只用智能体写周报。
AI 用哪家模型？
都可以。引擎层是协议抽象，Dify、DeepSeek、通义或任何 OpenAI 兼容端点自由切换，不锁定。
支持多少人？
定位 5–50 人小团队。三级角色（owner / member / readonly）+ 邀请链接机制。
手机能用吗？
微信小程序端已上线，含登录、工作台、项目、智能体与到期订阅消息提醒。
